## 綜合練習：部署故障調查助手

團隊設計一個調查助手。模型讀到日誌顯示資料庫連線逾時，接著查部署紀錄；兩位子代理分別查設定與資料庫，設定支線成功、資料庫支線因權限不足失敗。助手提出回滾建議，但沒有確認回滾核准。隔天設定檔又被工程師修改。請依序回答：

1. 讀日誌的 `tool_use` 後，執行環境必須把哪些資料放回下一輪對話？若模型輸出 `end_turn`，能否直接宣稱根因已證實？
2. 資料庫支線失敗時，協調者與綜整代理各需要看見哪些資訊？能否把「沒有查到資料」當成「資料庫無問題」？
3. 回滾前需要什麼程式化閘門？工具後 Hook 能否補救未核准但已執行的回滾？
4. 隔天該直接續接、定向重查，還是用摘要重開？哪些變更會改變選擇？若分叉兩條修復方案，還需要隔離什麼？

核對重點：工具請求與結果按 ID 配對回填；`end_turn` 只終止模型回合，根因須另驗證；失敗支線帶錯誤與覆蓋缺口進扇入；回滾權限須在執行前硬阻擋；已變更的設定須重新查證，會話分叉不會自動分叉外部工作目錄。
