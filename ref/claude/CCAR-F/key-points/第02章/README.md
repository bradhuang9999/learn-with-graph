要持續分清兩條界線：**MCP 工具與資源**可接入遠端議題庫、文件服務等外部能力；本機 `Grep`／`Glob`／`Read` 處理目前工作樹。兩者可能找到相似字詞，卻不代表資料來源、時間或權限相同。工具範圍也不同於工具選擇設定：前者界定能力與權限，後者約束單回合是否呼叫。

## 綜合練習

以「付款逾時後，客服回覆與產品文件不一致；請查證並修正程式訊息」為共同情境：

1. 議題查詢回傳 `items: []`，但同一呼叫 ID 的服務日誌顯示 403。能說「沒有議題」嗎？
2. 退款呼叫逾時後，代理想重試同一筆退款。只看到 `isRetryable: true` 是否足夠？
3. 查證代理與彙整代理都可能需要核對一句引文。應把全部查證工具交給彙整代理嗎？
4. 團隊共用的議題 Server 在 `.mcp.json`，新人仍看不到工具；個人實驗 Server 又只該在此專案使用。分別查哪裡、放哪裡？
5. `Grep` 找到 `chargeCard` 定義，`Edit` 又說錯誤字串不唯一。如何確認畫面呼叫端與安全修改目標？
6. `search_issues` 與 `search_local_export` 都寫成「搜尋議題」；代理因此常用過期匯出檔回答本週狀態。應如何修改工具描述與輸入契約？

**答案要點：**

1. 不行。403 是權限錯誤；成功空集合與查詢失敗須有不同結果訊號。
2. 不足。先查前次是否已產生副作用，或用冪等鍵；再看重試預算。逾時不等於操作未執行。
3. 不必。可提供受限、常用的 `verify_fact`；複雜查證交回協調者。
4. 先查專案 Server 核准、憑證、連線和工具發現；個人試驗放 `~/.claude.json` 的本機範圍，而非專案設定。
5. 讀匯出與包裝鏈、搜尋每個公開名稱；重讀含重複字串的全檔，先尋找唯一錨點，必要時全檔讀寫並核對差異，最後跑相關測試。
6. 先把來源邊界寫清：前者查遠端最新議題庫並回傳更新時間，後者只查本機匯出檔且不得用來證明即時狀態。兩者的描述應各自說明適用／不適用情境；輸入契約須明定議題範圍與日期欄位的格式，只有缺值便無法執行的欄位才設必填，日期若可安全預設則設為選用。後端仍須驗證，不靠描述取代權限或參數檢查。
