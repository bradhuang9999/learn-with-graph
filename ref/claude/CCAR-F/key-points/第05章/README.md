# 第 5 章｜Context 管理與可靠性

這一章把長時間執行的代理視為一條「證據與狀態」管線。模型能繼續說話，不代表關鍵數字仍在上下文中；子代理有回覆，不代表查詢成功；報告語氣篤定，也不代表每個主張都有可查證的來源。六節依次處理保存、分流、錯誤、探索、審查與追溯。

建議按下列路徑學習；每節也可獨立閱讀：

1. [5.1 在長互動中保留關鍵對話資訊](<5.1 在長互動中保留關鍵對話資訊.md>)：先保住事實與上下文預算。
2. [5.2 設計升級人工與歧義處理模式](<5.2 設計升級人工與歧義處理模式.md>)：再決定代理何時繼續、釐清或交接。
3. [5.3 在多代理系統中傳播錯誤](<5.3 在多代理系統中傳播錯誤.md>)：讓失敗以可恢復的資訊傳到協調者。
4. [5.4 在大型程式庫探索中管理 Context](<5.4 在大型程式庫探索中管理 Context.md>)：讓探索跨長對話與當機仍可續行。
5. [5.5 設計人工審查流程與信心校準](<5.5 設計人工審查流程與信心校準.md>)：用分群證據決定哪些結果能自動放行。
6. [5.6 保留資訊來源並處理多來源不確定性](<5.6 保留資訊來源並處理多來源不確定性.md>)：讓綜整結論可追溯、可核對、能誠實呈現衝突。

讀完可用同一個檢查問題串起全章：**這個輸出所依賴的事實是否仍在、查詢是否真的成功、決策是否符合人工交接規則、信心是否經過同類資料驗證、主張能否追到原始來源與時點？** 其中任何一環斷掉，流暢的回答都不足以證明可靠。

### 綜合練習

某退款代理在第 30 輪只記得「顧客要週五前退款」，官方政策庫逾時，另外兩位代理的結果彼此數值不同。請先列出：要從哪個來源恢復金額與顧客原話；逾時應回報哪種狀態與覆蓋缺口；兩個數值須核對哪些日期與口徑；若政策例外仍未查證，誰有權決定是否退款。能依序回答這四問，才算把第 5 章的資訊與決策邊界連成一條可靠流程。
