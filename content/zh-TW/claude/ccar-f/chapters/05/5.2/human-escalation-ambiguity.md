# 5.2 設計升級人工與歧義處理模式

## 原始考綱

**Task Statement 5.2：**設計有效的升級人工與歧義處理模式。

### 知識要求

- 適當的升級觸發條件：客戶要求人工、政策例外或缺口（不只是案件複雜），以及無法取得有意義的進展。
- 客戶明確要求人工時立即升級，與問題簡單時先提供解決方案，是不同情境。
- 情緒判斷與模型自行回報的信心分數，都不是案件實際複雜度的可靠替代指標。
- 工具回傳多筆可能的客戶資料時，應請求更多識別資訊，而非靠啟發式規則自行挑選。

### 技能要求

- 在系統提示加入明確升級標準與少樣本範例，示範何時升級、何時自主解決。
- 客戶明確要求人工處理者時立即尊重，不要先自行調查。
- 客戶表達挫折，但問題仍在 Agent 能力範圍時，先表示理解並提供解決方案；若客戶再次表明偏好人工，再升級。
- 政策對客戶的具體請求含糊或沒有規定時升級，例如政策只規範自家網站調價，未規範競品比價。
- 工具回傳多筆符合資料時，指示 Agent 詢問額外識別資訊，而非依啟發式規則選一筆。

## 要點筆記

升級人工(Escalation)是代理把決定權交給有權處理的人，不是「問題難」的同義詞。分流先看**顧客要求、政策授權、身分是否明確、是否仍能推進**；負面情緒與模型自報信心只能作輔助訊號，不能替代這些條件。

### 三條分流路徑

| 遇到的情況 | 應採動作 | 不應採動作 |
| --- | --- | --- |
| 顧客明確要求真人；政策對具體要求有空白或例外、代理無權裁定；或已無法有意義地推進 | **立即交接人工**。明確人工要求不須先額外調查，政策空白不能靠代理自行創造規則。 | 用「我應該能處理」拖延交接；把高信心當作授權 |
| 查到多筆可能客戶或訂單，缺少可區分的識別資料 | **先釐清**，請求最少必要識別碼並依既定身分驗證流程查詢；無法核實才進人工驗證。 | 依名稱相似、時間較近或分數較高猜一筆，或洩露候選人的資料 |
| 顧客不滿，但問題在明確政策與工具能力內 | **承認不便並處理問題**，同時保留人工選項；顧客再次要求真人就交接。 | 只因語氣激烈而過早升級，或只安撫卻不採取可行動作 |

這些條件可寫成系統指示，並用少量帶理由的正反範例標出邊界：「我要真人」直接交接；「這很煩，請查物流」先查物流；「搜尋回兩位同名客戶」先核對識別；「政策只寫自家網站調價，顧客要求競品比價」交有權者決定。範例教的是**判斷條件**，不是讓代理死背關鍵字。

其中「顧客明確要求人工」及「代理無權裁定政策例外」是**硬觸發**：條件成立就交接，不拿模型自報信心重新投票。挫折語氣或處理難度是較軟的訊號，須結合政策範圍與已查結果判斷；「信心 95%」不能把多筆候選資料變成單一已驗證身分。若案件在代理能力內，就先處理並保留人工選項；若連續嘗試後仍無進展，應停止無效重試並交接。

### 交接要傳遞什麼

交接承載內容(Handoff Payload)須讓接手者不用重讀整段對話就能採取下一步，至少有四項：

1. **脈絡摘要**：案件目標、已確認的識別資訊及目前狀態。
2. **觸發原文與原因**：保留顧客明確要求或政策缺口的原話，標明代理為何不能自行決定。
3. **已嘗試的行動與結果**：查了哪個工具、驗證了什麼、重試幾次、哪些資料仍未核實；不要把未驗證候選人寫成確定客戶。
4. **待決問題與建議下一步**：請人工裁定哪件事、可能的處理方向；建議不是先行授權。

升級不能只在一般文字說「我需要幫忙」後繼續執行。系統可提供一個結構化的 `request_review`／`escalate` 求助工具，由代理提交上述欄位並使案件進入待審狀態；協調者依觸發類型和權限路由，記錄目的地與結果。以競品價差退款為例，概念上的提交欄位可為 `trigger=政策未涵蓋競品比價`、`customer_quote=「請依競品價格退差額」`、`verified_order=A-71`、`attempts=已查訂單與自家調價政策`、`decision_needed=是否准許例外`。這是交接契約的示意，**不是固定 SDK 呼叫語法**；若沒有觸發和已查結果等結構，接手者仍須重讀全文，也無法可靠分流。提出求助後，任何尚未核准的退款等不可逆操作應暫停，不能一邊等待人工一邊繼續執行。

交接不是傾倒全文。結構化欄位使協調者能依權限把案件送往人工審查、專業代理或監督者，並留下觸發類型、路由目的地與最終結果，以找出反覆升級的政策缺口。若待決事項是不可逆退款，審查點須在執行前；若人工處理跨工作階段，先外存案件與進度，設定回覆期限和逾時時的安全動作，不能讓未核准的操作因等待過久而自動通過。

### 完成閉環：人工決定須回到原流程

以競品價差退款為例：代理記錄顧客原話、已核實訂單金額、政策只涵蓋自家網站調價，以及**尚未退款**，交人工判斷。人工回覆「不適用競品比價」後，決策和理由須回寫同一案件狀態；代理讀回後，才能向顧客說明並繼續其他獨立訴求。完整路徑是**暫停 → 人工決定 → 狀態回注 → 從中斷點續作**。缺少回注，代理可能再次為同一缺口升級，或在不知道人工已拒絕的情況下繼續執行。

**判斷練習**：工具回兩筆同名訂單，其中一筆日期較近，代理自報 95% 把握。可以直接選嗎？不能。這是身分歧義，不是統計猜測題；應索取可區分的識別資訊，必要時走人工驗證。
