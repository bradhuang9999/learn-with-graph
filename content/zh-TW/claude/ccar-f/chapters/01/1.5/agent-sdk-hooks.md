# 1.5 用 Agent SDK Hooks 攔截工具呼叫並正規化資料

## 原始考綱

### 知識要求

- 攔截工具結果並在模型處理前轉換的 Hook 模式，例如 `PostToolUse`。
- 攔截即將發出的工具呼叫以強制遵守規則的 Hook 模式，例如阻擋超過門檻的退款。
- 使用 Hook 提供確定性保障，與依賴提示指令取得機率性遵循之間的差別。

### 技能要求

- 實作 `PostToolUse` Hook，在 Agent 處理前將不同 MCP 工具的異質資料格式（Unix 時間戳、ISO 8601、數字狀態碼）正規化。
- 實作工具呼叫攔截 Hook，阻擋違反政策的動作（如超過 500 美元的退款），並轉入其他流程（如升級人工）。
- 當業務規則要求保證遵守時，選用 Hook，而非只用提示詞強制。

## 要點筆記

### 工具邊界的兩個控制點

**Hook** 是在代理流程的指定事件點執行的程式邏輯。工具邊界有兩個不可互換的控制點：工具**執行前**可檢查並阻擋高風險呼叫；工具**執行後、模型讀取結果前**可轉換異質資料。前者防止副作用，後者防止模型誤解回傳值。兩者都比只在提示詞中要求「務必遵守」更適合確定性的政策或格式規則。

| 控制點 | 看得到什麼 | 能做什麼 | 做不到什麼 |
|---|---|---|---|
| 工具前，如 `PreToolUse` | 工具名稱、待送出的參數及可查得的政策狀態 | 拒絕違規呼叫、要求補資料或導向人工流程 | 不能轉換尚未產生的工具結果 |
| 工具後，如 `PostToolUse` | 已取得的原始工具回傳 | 統一時間、狀態等格式，標出未知值並保留來源 | 不能撤銷工具已造成的退款或寫入 |

### 工具前：把政策做成硬性決策

若政策規定超過 USD 500 不得自動退款，模型提出 `process_refund({amount:620,currency:"USD"})` 時，工具前 Hook 檢查金額、幣別、客戶驗證與核准狀態，回傳拒絕理由；退款工具**沒有執行**。應用程式再建立待人工核准事項，不能把「工具被拒絕」誤當「人工案件已建立」。剛好達上限、超額、缺金額、幣別不明或政策查詢失敗都須有明確分支；不能在無法判定時猜測放行。

同樣的輸入和政策狀態由程式得出同樣結果，才是這裡的「確定性」。它不表示代理的研究與推理都變成確定性。1.4 的身分閘門可直接設在應用程式工具層，也可用工具前 Hook 實作；不論位置在哪裡，不可協商的條件都必須在工具執行前通過。本文所據 SDK 範例中的 `PreToolUse` 阻擋決策可由 `hookSpecificOutput.permissionDecision: "deny"` 與理由表達，但實際欄位須以所用 SDK 版本為準。

實作時，先把 `PreToolUse` callback 註冊在退款工具的呼叫邊界，再把判斷寫成可測的輸入→輸出契約：輸入是工具名稱、金額、幣別、已驗證身分與政策門檻；輸出只有「允許執行」或「拒絕並附原因」。以同一政策狀態測試 USD 500、USD 620、缺幣別與政策查詢失敗，確認後三種情況不會碰到退款工具；拒絕後另由應用流程建立人工待辦。Hook 的拒絕結果本身不代表人工已接單。

### 工具後：把來源格式轉成可比較的觀察

`PostToolUse` 在工具回傳後、模型處理結果前運作。正規化不是把不同原始資料硬改成相同意義，而是依**每個來源自己的規格**轉成共同的欄位：

1. 確認來源與單位，例如 Unix 時戳是秒還是毫秒，狀態碼 `2` 在此工具代表什麼。
2. 轉為約定格式，例如含時區的 ISO 8601 時間，以及「完成／待人工／未知」等語意狀態。
3. 保留原值、來源及轉換錯誤。未定義的狀態碼不能猜成成功；單位不明的時間不能猜一個日期。

例如訂單工具回傳秒級時戳 `1764547200`，工單工具回傳 `2025-12-01T00:00:00Z`；確認單位後兩者可標準化為同一 UTC 時刻。但若訂單的 `status=2` 是「完成」，工單的 `status=2` 是「待人工」，轉換後仍須保留不同語意。第三個工具若回傳未知的 `status=9`，應標「未知」並附原碼 9，不自行推論案件已結束。

若要讓模型**讀到替換後的內容**，所用 SDK 的 `PostToolUse` callback 須回傳對應的更新工具輸出欄位；本文所據版本使用 `hookSpecificOutput.updatedToolOutput`。`additionalContext` 只是在原結果旁追加說明，不能當成已替換原值；較舊的 `updatedMCPToolOutput` 有較窄的用途。這些產品欄位具版本敏感性，實作時應核對安裝版本。即使事後發現結果格式有錯，也不能靠工具後 Hook 補救早已發生的政策違規。

`PostToolUse` 的實作契約也可按輸入→輸出檢查：callback 接收工具名稱與原始回傳，依該工具的時間單位和狀態碼對照表，產生「統一時間、語意狀態、原值、來源、轉換錯誤」；再把這份結果作為更新後的工具輸出回傳，確認下一輪模型讀到的是正規化值。測試至少涵蓋秒與毫秒時戳、不同來源的同號狀態碼、未知狀態碼及格式錯誤；不明值保留為未知，不得默認成功。
